## 2. التقنيات

| الجزء | الاختيار المقترح | السبب |
|---|---|---|
| الإطار | **Svelte 5 + TypeScript** ✅ | كود قليل وواضح، حجم صغير وسريع على الجوال، والتفاعل (المؤقتات وحالة الأسئلة) سهل |

**البدائل:**
- **React:** أشهر وأوسع انتشاراً، لكن الكود أطول.
- **بلا إطار** (JavaScript فقط): لا حاجة لتعلم إطار، لكن إدارة الحالة والواجهة تصبح يدوية ومعرضة للأخطاء.

## 4. نموذج البيانات (localStorage)

كل المفاتيح تبدأ بـ `osq:v1:`. رقم الإصدار يسمح بترحيل البيانات إذا تغير شكلها مستقبلاً.

| المفتاح | المحتوى |
|---|---|
| `osq:v1:active` | الاختبار غير المكتمل (واحد فقط)، أو لا شيء |
| `osq:v1:history` | قائمة الاختبارات المكتملة |
| `osq:v1:seen` | لكل سؤال: آخر وقت ظهر فيه وعدد مرات ظهوره (لتفادي التكرار) |

**شكل الاختبار (Attempt):**
```ts
{
  id: string,                 // معرّف عشوائي
  createdAt, finishedAt,      // تواريخ
  units: number[],            // الوحدات المختارة
  items: [{
    qid: "c3-021",            // رقم السؤال في البنك
    order: [2, 0, 3, 1],      // ترتيب عرض الخيارات (خلط)
    answer: 1 | null,         // إجابة المستخدم بترقيم البنك الأصلي، وليس ترتيب العرض
    flagged: boolean,
    timeMs: number,           // الوقت التراكمي على السؤال (لعداد التلميح)
    hintShown: boolean
  }],
  current: number,            // السؤال الحالي
  elapsedMs: number,          // المؤقت الكلي
  retakeOf?: string           // إن كان إعادة لاختبار سابق
}
```
- **حفظ الإجابة بترقيم البنك الأصلي** يضمن صحة التصحيح مهما كان ترتيب العرض.
- **السجل يحفظ أرقام الأسئلة فقط، لا نصها.** إذا حُذف سؤال من البنك لاحقاً، تظهر مكانه عبارة "سؤال محذوف" في المراجعة بدل أن تتعطل الصفحة.
- **الحفظ التلقائي** يحدث بعد كل تغيير، وكل ثانية للمؤقتات.
- **كل قراءة وكتابة في التخزين محمية بـ try/catch**، لكي يعمل الموقع حتى لو كان التخزين معطلاً (مثل التصفح الخفي)، مع تنبيه للمستخدم.

## 5. المنطق الأساسي

### 5.1 اختيار الأسئلة
1. توزيع العدد المطلوب على الوحدات المختارة بالتساوي، والباقي يوزَّع عشوائياً.
2. إذا لم تكفِ أسئلة وحدة، يُكمَّل النقص من الوحدات الأخرى المختارة.
3. داخل كل وحدة تُفضَّل الأسئلة الأقل ظهوراً ثم الأقدم ظهوراً، ويُكسر التعادل عشوائياً.
4. يُخلط ترتيب الأسئلة وترتيب خيارات كل سؤال.
- **Retake (same):** نفس الأسئلة بترتيب جديد للأسئلة والخيارات.
- **Retake (new):** نفس الوحدات ونفس العدد، مع تطبيق الخطوات من 1 إلى 4 (تفادي التكرار).

### 5.2 المؤقتات
- **المؤقت الكلي** تصاعدي، ويتوقف عند Save & Exit أو عند إغلاق الصفحة.
- **التبويب المخفي ✅:** **يستمر العد** إذا انتقل المستخدم لتبويب آخر والاختبار مفتوح، لأن الهدف قياس مدة الاختبار الفعلية.
- **عداد التلميح** تنازلي من دقيقتين لكل سؤال، ولا يعدّ إلا والسؤال معروض. الوقت تراكمي، والتلميح يبقى ظاهراً بعد ظهوره.
- **"Clear answer":** زر صغير لإلغاء الإجابة المختارة وإرجاع السؤال لغير مُجاب.
- **قياس الوقت** بالفرق بين لحظتين (`Date.now()`) وليس بعدّ النبضات، لكي يبقى دقيقاً حتى لو أبطأ المتصفح التبويب.

### 5.3 التقدير
- النسبة = الصحيح ÷ العدد الكلي، وغير المجاب يُحسب خاطئاً.
- السلّم: 90 فأعلى Excellent، و80 Very Good، و70 Good، و60 Pass، وأقل من 60 Fail.

## 6. تجربة الاستخدام
- **التصميم:** داكن، وأولويته الوضوح وسرعة الاستخدام، والجوال أولاً.
- **لا توجد اختصارات للوحة المفاتيح** (قرار صاحب المشروع)، والاستخدام بالضغط فقط.
- **الوصولية:** عناصر تحكم قياسية (أزرار وروابط حقيقية تعمل مع Tab وEnter)، وتباين ألوان كافٍ، وأزرار كبيرة للمس.
- **عرض أسئلة الجدولة:** جدول العمليات، والكود بخط ثابت العرض.

## 8. النشر
- **GitHub Pages** عبر GitHub Actions: البناء والنشر تلقائياً عند كل push إلى `main`. مجاني ويكفي تماماً.
- حساب GitHub متوفر ✅، والمستودع عام.
- **الملفات:** `.github/workflows/deploy.yml` (فحص البنك والأنواع واختبارات المنطق ثم البناء والنشر)، و`tools/publish.sh` للنشر أول مرة (إنشاء المستودع وتفعيل Pages والرفع).
- المستودع يمكن أن يكون عاماً أو خاصاً. **الخاص يحتاج اشتراكاً مدفوعاً لاستخدام Pages**، لذلك المستودع العام هو الخيار المجاني.
